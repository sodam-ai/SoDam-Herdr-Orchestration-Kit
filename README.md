# SoDam Herdr Orchestration Kit

**한국어** | [English](README.en.md) · 같은 내용의 웹 문서: [README.html](README.html) · [README.en.html](README.en.html)

여러 개의 AI 창(Claude Code)을 한꺼번에 돌릴 때, **누가 어떤 일을 맡는지(역할)** 를 파일 하나로 정해 두고, 그 역할을 **다른 컴퓨터로 옮기거나, 고치거나, 백업하고 되돌릴 수 있게** 해 주는 도구 모음입니다.

> **현재 상태 (먼저 읽어 주세요)**
>
> - 버전 `0.1.1`. 개발 중인 초기 버전입니다.

> - 이 도구는 기본으로 **어느 AI 창에도 글자나 키를 보내지 않습니다.** 보내는 기능(승인 대행, 자동 압축)은 설치 직후 **모두 꺼져 있습니다.**

## 2. 이 도구는 무엇인가요?

### 한 줄 설명

AI 창 여러 개가 **각자 맡은 일(역할)** 을 적은 문서를 안전하게 관리하는 도구입니다.

### 비유로 이해하기

회사에 팀원 12명이 있다고 생각해 보세요. "누가 무슨 일을 하고, 누구에게 보고하는지"를 적은 **업무 분장표**가 있습니다. 이 도구는 그 분장표를

- 한 곳(역할 파일)에서만 고치면 모든 안내문이 자동으로 같이 바뀌게 하고,
- 다른 컴퓨터(새 회사)로 **통째로 옮길 수 있게** 하고,
- 고치기 전에 **자동으로 사본(백업)** 을 만들어 실수해도 되돌릴 수 있게 합니다.

### 이 도구가 하는 일 / 하지 않는 일

| 하는 일 | 하지 않는 일 |
|---|---|
| 역할 12개의 정의를 파일로 보관 | AI 창에 글자·키 보내기(기본값) |
| 역할표·역할 카드·탭 배치 계획 만들기 (`sync`) | 인터넷으로 정보 보내기 (코드에 인터넷 접속 부분이 없습니다) |
| 역할 보기·수정·새로 만들기·되돌리기·삭제 | 사용자의 폴더를 통째로 지우기 |
| 역할 묶음 내보내기·불러오기 (다른 PC로 이동) | 허락 없이 설정 파일 덮어쓰기 |
| 자동 백업과 복구 | Herdr 앱 자체나 AI 대화 기록 수정 |
| 지금 열려 있는 창 목록 보기 (읽기 전용) | 시작 프로그램·작업 스케줄러·레지스트리·PATH 변경 |

### 용어 쉬운 풀이

| 용어 | 뜻 |
|---|---|
| **터미널 / PowerShell** | 글자로 명령을 입력하는 검은(또는 파란) 창입니다. 시작 메뉴에서 "PowerShell"을 검색하면 열립니다. |
| **명령어** | 터미널에 입력하고 Enter를 누르는 한 줄짜리 지시입니다. 이 문서의 회색 상자 안 글자를 **그대로 복사해서 붙여넣으면** 됩니다. |
| **폴더 / 경로** | 파일이 들어 있는 곳과 그 주소입니다. 예: `C:\Users\내이름\Downloads` |
| **Node.js** | 이 도구의 핵심 프로그램(`.mjs` 파일)을 실행해 주는 무료 프로그램입니다. 따로 설치해야 합니다. |
| **Herdr** | 여러 터미널(AI 창)을 한 화면에 모아서 보여 주는 앱입니다. **이 저장소에 들어 있지 않은 별도 프로그램**입니다. |
| **`hc`** | Herdr 안의 창들을 조회·제어하는 명령줄 도구입니다. 이 저장소에 들어 있지 않습니다. |
| **Claude Code** | 터미널에서 쓰는 Anthropic의 AI 코딩 도구입니다. 이 도구가 다루는 "AI 창"의 대부분이 이것입니다. |
| **역할(role)** | AI 창 하나가 맡는 일의 정의입니다. 예: "검증관", "보안 점검관". `roles\` 폴더의 `.md` 파일 하나가 역할 하나입니다. |
| **총지휘(commander)** | 다른 역할 창에 일을 나눠 주고 결과를 모아 사용자에게 보고하는 역할입니다. |
| **sync** | 역할 파일들을 읽어 역할표·카드·탭 배치 계획을 새로 만드는 단계입니다. |
| **모드(mod)** | Herdr 안에 끼워 넣는 작은 창 프로그램입니다. 이 도구의 "관리 창"이 모드로도 들어 있습니다. |
| **플러그인 / 마켓플레이스** | Claude Code에 기능을 추가하는 꾸러미와, 그 꾸러미를 모아 둔 목록입니다. |
| **환경변수** | 프로그램이 읽는 "설정 쪽지"입니다. 이 도구는 `ORCH_HOME`(설정 보관 위치)을 읽습니다. |
| **백업 / 복구** | 바꾸기 전의 사본을 저장해 두는 것 / 그 사본으로 되돌리는 것입니다. |

## 3. 준비물과 필요한 프로그램

| 필요한 것 | 필수? | 설명 |
|---|---|---|
| **Windows 10 또는 11** | 필수 | 이 도구는 Windows 전용입니다. 개발과 시험은 Windows 11에서만 했습니다. Windows 10은 확인하지 않았습니다. |
| **Windows PowerShell 5.1** | 필수 | Windows에 기본으로 들어 있습니다. 설치할 것이 없습니다. |
| **Node.js 18 이상** | 필수 | 설치 프로그램이 18 미만이면 "중단"하고 멈춥니다. 개발과 시험은 최신 버전(26.7.0)에서 했고, 18~25 버전은 직접 확인하지 못했습니다. 받는 곳: <https://nodejs.org> 의 **LTS** 버튼. |
| **Herdr 앱** | 선택 | "허더 안에서 여는 관리 창"을 쓰려면 필요합니다. 없어도 별도 Windows 창으로 쓸 수 있습니다. Herdr의 배포처와 사용 조건은 이 저장소에서 확인하지 못했으니 제공처의 안내를 따르세요. |
| **`hc` 명령** | 선택 | "실제 창" 탭과 `functions` 스크립트들이 씁니다. 없으면 그 부분만 "조회 불가"로 안내하고 나머지는 정상 동작합니다. |
| **Claude Code** | 선택 | 마켓플레이스 플러그인으로 설치할 때, 그리고 AI 창으로 역할을 실제 운영할 때 필요합니다. |
| **Git** | 선택 | `git clone`으로 내려받을 때만 필요합니다. ZIP 파일로 받으면 필요 없습니다. |
| **관리자 권한** | 불필요 | 설치는 일반 사용자 권한으로 됩니다. |
| **인터넷** | 설치 때만 | Node.js를 내려받을 때만 필요합니다. 이 도구 자체는 인터넷을 쓰지 않습니다. |

**Node.js가 이미 있는지 확인하기** — PowerShell을 열고 아래를 입력하세요. `v18` 이상 숫자가 나오면 됩니다.

```
node -v
```

`node` 를 찾을 수 없다는 글이 나오면 Node.js LTS를 설치한 뒤, **PowerShell 창을 닫고 새로 열어** 다시 확인하세요(새 창이어야 인식됩니다).

## 5. 설치 방법

설치 방법은 세 가지입니다. **방법 1을 먼저 하는 것을 권장합니다.** 방법 2는 방법 1을 한 뒤에 선택으로 추가합니다.

> **PowerShell을 프로젝트 폴더에서 여는 법:** 탐색기에서 프로젝트 폴더(`bin` 폴더가 보이는 폴더)를 열고, 위쪽 주소창을 클릭해 주소를 복사합니다. PowerShell을 열고 `cd "` 를 입력한 뒤 붙여넣고 `"` 로 닫고 Enter. 예: `cd "C:\Users\내이름\Downloads\SoDam-Herdr-Orchestration-Kit"`

> **명령에 `-ExecutionPolicy Bypass` 가 붙는 이유:** Windows는 기본적으로 내려받은 `.ps1` 실행을 막을 수 있습니다. 이 옵션은 **그 한 번의 실행에만** 제한을 풉니다. 컴퓨터 전체 설정은 바뀌지 않습니다.

### 방법 1 — 기본 설치 (필수 · 별도 Windows 창)

**1단계: 점검만 해 보기** (아무것도 바꾸지 않습니다)

```
powershell -NoProfile -ExecutionPolicy Bypass -File bin\install.ps1 -Check
```

마지막 줄에 `점검 결과: 중단 0건` 이 나오면 설치할 수 있습니다. **경고**는 "설치는 되지만 일부 기능이 제한됨"이라는 뜻이라 정상일 수 있습니다(예: Herdr 세션키퍼가 없음, 허용 목록이 아직 없음). **중단**이 하나라도 있으면 그 이유 글을 읽고 해결한 뒤 다시 하세요.

**2단계: 설치**

```
powershell -NoProfile -ExecutionPolicy Bypass -File bin\install.ps1
```

설치가 하는 일:

- 프로그램 파일을 `%LOCALAPPDATA%\Herdr-Orchestration\app` 에 **복사**합니다(보통 `C:\Users\내이름\AppData\Local\Herdr-Orchestration\app`).
- 같은 곳에 `config`(설정), `state`(작업 기록), `logs`(로그) 폴더를 **처음 한 번만** 만듭니다. 이미 있으면 **덮어쓰지 않습니다.**
- 위험 기능을 **모두 꺼진 상태**로 등록합니다.

설치가 하지 않는 일: 시작 프로그램·작업 스케줄러·레지스트리·PATH 변경, 어느 창에든 입력 보내기.

설치 위치를 바꾸고 싶다면 옵션을 덧붙입니다.

| 옵션 | 뜻 |
|---|---|
| `-OrchHome <폴더>` | 설정·기록을 둘 위치(기본: 환경변수 `ORCH_HOME`, 없으면 `%LOCALAPPDATA%\Herdr-Orchestration`) |
| `-InstallDir <폴더>` | 프로그램 파일 위치(기본: `<OrchHome>\app`) |
| `-DocsDir <폴더>` | 문서 폴더(기본: `<OrchHome>\state\docs`) |
| `-Force` | 비어 있지 않은 다른 폴더에도 설치하도록 허용 |
| `-Check` | 점검만 |

> **기본 위치가 아니라면:** 사용할 때마다 환경변수 `ORCH_HOME` 을 그 위치로 지정해야 합니다(설치가 끝날 때 안내 글이 나옵니다). 예: `$env:ORCH_HOME = "D:\내폴더\orch-home"` (이 PowerShell 창에서만 유효).

<a id="s5-2"></a>
### 방법 2 — Herdr 안에서 여는 관리 창(모드) 설치 (선택)

Herdr 앱 **안에서** 단축키로 여는 창입니다. Herdr가 설치되어 있어야 합니다. **방법 1을 먼저 하세요.**

```
powershell -NoProfile -ExecutionPolicy Bypass -File bin\install-herdr-mod.ps1 -Check
```

문제가 없으면 `-Check` 를 빼고 다시 실행합니다.

```
powershell -NoProfile -ExecutionPolicy Bypass -File bin\install-herdr-mod.ps1
```

이 설치가 하는 일:

1. 모드 파일을 임시 폴더에 만들고, **Herdr 공식 검사(`herdr-app check`)를 먼저** 돌립니다. 통과하지 못하면 **아무것도 설치하지 않고** 멈춥니다.
2. 통과하면 Herdr 설정 폴더의 `mods\orch-manager` 에 복사합니다(기본 `~\.config\herdr-app`).
3. Herdr의 `keys.json` 맨 앞에 열기 단축키 **한 줄**(기본 `ctrl-shift-m`)을 추가합니다. **먼저 백업**(`keys.json.bak-before-orch-manager`)을 만들고, 결과가 올바른 JSON이 아니면 파일을 그대로 둡니다. 이미 그 키가 쓰이고 있으면 건너뜁니다.

건드리는 곳은 `mods\orch-manager` 폴더와 `keys.json` 한 줄뿐입니다. 다른 모드·레이아웃·설정·터미널·대화 기록은 손대지 않습니다.

| 옵션 | 뜻 |
|---|---|
| `-Key <키>` | 열기 단축키 변경(예: `ctrl-shift-o`) |
| `-NoKey` | 단축키를 연결하지 않음. 명령 팔레트(`Ctrl+Shift+P`)에서 `mod.open orch-manager` 로만 엽니다. |
| `-HerdrHome <폴더>` | Herdr 설정 폴더(기본: 환경변수 `HERDR_APP_HOME`, 없으면 `~\.config\herdr-app`) |
| `-HerdrApp <파일>` | `herdr-app.exe` 위치(기본 `%LOCALAPPDATA%\Programs\herdr-app\herdr-app.exe`) |
| `-Uninstall` | 제거(우리가 만든 파일만 지우고 키 한 줄을 뺌) |

<a id="s5-3"></a>
### 방법 3 — Claude Code 마켓플레이스 플러그인 (선택)

이 저장소는 Claude Code 마켓플레이스(`.claude-plugin\marketplace.json`)이고, 플러그인 이름은 `herdr-orchestration-manager`(버전 0.1.1) 입니다. 플러그인 안의 설치 도우미 스킬이 위 방법 1과 방법 2를 **순서대로** 실행해 줍니다. 플러그인 폴더의 `install.ps1` 을 직접 실행해도 같습니다.

```
powershell -NoProfile -ExecutionPolicy Bypass -File plugins\herdr-orchestration-manager\install.ps1 -Check
```

> 마켓플레이스 주소로 원격 설치하는 과정은 이 문서를 쓰면서 **직접 실행해 확인하지 못했습니다.** 플러그인 폴더의 설치 흐름 전체는 자동 시험(`tests\plugin.test.mjs`)에서 확인했습니다.

<a id="s6"></a>
## 6. 빠른 시작 (처음부터 끝까지 따라 하기)

**전체 소요: 약 5분.** 아래를 **위에서 아래로 순서대로** 하세요.

1. Node.js 확인: `node -v` → `v18` 이상이면 통과 ([3장](#s3)).
2. 프로젝트 폴더에서 PowerShell 열기 ([5장](#s5) 안내).
3. 점검: `powershell -NoProfile -ExecutionPolicy Bypass -File bin\install.ps1 -Check` → `중단 0건` 확인.
4. 설치: `-Check` 를 뺀 같은 명령.
5. **설정 파일 열기.** 메모장으로 `%LOCALAPPDATA%\Herdr-Orchestration\config\orchestration.json` 을 엽니다(탐색기 주소창에 `%LOCALAPPDATA%\Herdr-Orchestration\config` 를 붙여넣으면 이동합니다). 아래 값을 **이 컴퓨터에 맞게** 고치고 저장하세요.

   | 항목 | 기본값 | 무엇을 적나요 |
   |---|---|---|
   | `scope_prefix` | `(미설정)` | 관리할 Herdr 공간(space) 이름의 앞부분 |
   | `projects_root` | `(미설정)` | 프로젝트 폴더들이 모여 있는 상위 폴더 |
   | `commander_name` | `orch-commander` | 총지휘 창에 붙일 이름(소문자·숫자·`-`·`_`, 1~32자) |
   | `control_dir` | `<설정 위치>\control` | 지휘용 기록 파일을 둘 폴더 |

   > `(미설정)` 으로 두면 `sync` 가 "해당 범위의 창은 하나도 잡히지 않습니다"라는 경고를 냅니다. 오류로 멈추지는 않지만, 값을 채워야 실제로 쓸 수 있습니다.

6. 생성물 만들기 (설치 폴더 기준, `<ORCH_HOME>` 이 기본 위치라면 환경변수 지정 불필요):

   ```
   node "%LOCALAPPDATA%\Herdr-Orchestration\app\bin\sync.mjs"
   ```

   성공하면 `sync 완료: 역할 12개 (켜짐 11, 꺼짐 1) → 역할표 1, 카드 11, 탭 4개 계획` 이 나옵니다. 결과 파일은 `%LOCALAPPDATA%\Herdr-Orchestration\state\generated` 에 생깁니다.

7. 관리 창 열기: `%LOCALAPPDATA%\Herdr-Orchestration\app\bin\Herdr-Orchestration-Manager.vbs` 를 **더블클릭**.
8. (선택) Herdr 안의 관리 창: [5장 방법 2](#s5-2) 후 Herdr에서 `Ctrl+Shift+M`.

## 8. 사용 방법 (관리 창)

Windows 창과 Herdr 안의 창은 **같은 엔진**을 씁니다. 화면에 쓰인 말(모드·주기 이름 등)도 같게 맞춰 두었습니다. 탭은 다음과 같습니다(Herdr 안의 창에는 마지막에 "단축키" 탭이 하나 더 있습니다).

| 탭 | 하는 일 |
|---|---|
| **현황** | 설치 상태(버전, 설정·백업 위치, 역할 수와 문제 등)를 보여 줍니다. **[sync 실행 (생성물 갱신)]** 버튼으로 역할표·카드·배치 계획을 새로 만듭니다. |
| **역할 편집** | 역할 목록에서 하나를 골라 이름·요약·자리·모드·주기·보고 대상 등을 고치고 **[저장]** 합니다. **[끄기 / 켜기]**, **[번들 값으로 되돌리기]**, **[새 역할 만들기...]**, **[내가 만든 역할 삭제]** 도 여기서 합니다. |
| **내보내기·불러오기** | **[내보내기]** 로 내 역할 묶음을 폴더로 저장하고, **[미리보기...]** 로 다른 PC의 묶음을 불러옵니다. 불러오기는 **미리보기를 먼저** 보여 주고, 적용 직전에 한 번 더 "정말 적용할까요?"를 묻습니다. |
| **백업 · 복구** | **[지금 백업]**, 백업 목록 보기, **[선택한 백업으로 복구...]**(미리보기 후 적용), **[백업 폴더 열기]**. |
| **실제 창** | 지금 Herdr에 열려 있는 창 목록을 **읽기만** 합니다. **[선택한 창 주소 복사]** 로 창 주소를 복사할 수 있습니다. `hc` 가 없으면 "조회 불가"라고 안내합니다. |
| **단축키** (Herdr 안 창만) | 이 창을 여는 키를 바꾸고, 실제 파일에 반영되는지 "저장 진단"으로 확인합니다. |

> 버튼 이름은 Windows 관리 창 기준입니다. Herdr 안의 창은 같은 기능을 비슷한 이름의 버튼으로 제공합니다. **[번들 값으로 되돌리기]** 는 내가 번들 역할에 덧씌운 변경을 지우고 처음 상태로 돌리는 기능이고, **[내가 만든 역할 삭제]** 는 내가 새로 만든 역할만 지웁니다(번들 역할은 지울 수 없습니다).

Herdr 안 창의 키보드: `Esc` 닫기 · `Ctrl+1`~`Ctrl+6` 탭 이동 · `F5` 새로고침 · `Ctrl+S` 저장(역할 편집 탭에서).

### 역할 하나 고치기 (예시)

1. 관리 창을 엽니다 → **역할 편집** 탭.
2. 목록에서 고칠 역할(예: "검증관")을 클릭합니다.
3. 값을 고칩니다. 예: 주기를 "요청 시 (on-request)"에서 "주기적 (periodic)"으로.
4. **[저장]**. 저장 직전에, **백업할 "내 설정" 파일이 이미 있으면 자동으로 백업**이 만들어집니다. (처음 고치는 경우처럼 내 파일이 아직 하나도 없으면 백업할 것이 없어 만들어지지 않습니다. 번들은 바뀌지 않으므로 **[번들 값으로 되돌리기]** 로 처음 상태로 돌릴 수 있습니다.) 결과가 규칙에 맞지 않으면 **아무것도 쓰지 않고** 이유를 알려 줍니다.
5. 저장 후 **sync를 다시 실행**하면 역할표와 카드가 새 내용으로 바뀝니다(관리 창 "현황" 탭의 **[sync 실행 (생성물 갱신)]** 또는 [10장](#s10)의 명령).

### 모드·주기 이름

| 화면 표시 | 저장되는 값 | 뜻 |
|---|---|---|
| 읽기 전용 (read-only) | `read-only` | 파일을 읽기만 함 |
| 범위 내 쓰기 (scoped-write) | `scoped-write` | 정해 둔 곳(`writes_to`)에만 쓸 수 있음 |
| 요청 시 (on-request) | `on-request` | 부탁받았을 때만 일함 |
| 주기적 (periodic) | `periodic` | 정해진 간격으로 일함 |

### 다른 PC로 옮기기

1. 원래 PC: **내보내기·불러오기** 탭에서 폴더를 지정해 내보냅니다. 폴더 안에 `orch-export-날짜-시각` 이라는 **하위 폴더**가 만들어지고, 그 안에 `package.json` 과 파일들이 들어 있습니다.
2. 그 하위 폴더 전체를 USB·클라우드 등으로 새 PC에 옮깁니다.
3. 새 PC: 이 도구를 설치한 뒤, **내보내기·불러오기** 탭에서 **`orch-export-…` 하위 폴더**를 지정해 **미리보기**를 봅니다. (상위 폴더를 지정하면 "묶음 폴더가 아님"이라고 나옵니다.)
4. 내용이 맞으면 적용합니다. **남의 묶음에서 온 새 역할과 바뀌는 역할은 "꺼진 채"로 들어옵니다.** 본문이 AI 창이 따르는 지시문이기 때문이니, **내용을 읽어 보고** 직접 켜세요.

## 9. 작동 방법 (내부 원리)

1. **역할 파일** (`roles\*.md`): 맨 위 `---` 사이에 이름·요약·자리·모드·주기·보고 대상 같은 **항목**이 있고, 아래에 AI 창이 따를 **본문**이 있습니다. 항목 형식은 `schema\role.schema.json` 이 정합니다.
2. **내 역할 폴더** (`<설정 위치>\config\roles`): 같은 id의 파일을 두면 번들 역할을 **덮어쓰고**(바꾼 항목만 적으면 됨), 새 id는 **새 역할**이 됩니다. 업그레이드해도 이 폴더는 건드리지 않습니다.
3. **설정** (`orchestration.json`): 경로·이름은 코드에 적지 않고 여기서 읽습니다.
4. **sync**: 역할(번들 + 내 역할)과 설정을 합쳐 `역할표.md`, 역할 카드(`cards\<역할id>.md`), 탭 배치 계획(`layout-plan.json`), 목록(`sync-manifest.json`)을 만듭니다. **계획과 문서만 만들고**, 창을 만들거나 `hc` 를 부르거나 어느 창에도 아무것도 보내지 않습니다. 검증에 실패하면 이전 출력을 그대로 둡니다.
5. **탭 배치 규칙**: 탭 이름은 **자리 번호**로 정해집니다(기본: 자리 1~4, 5~8, 9~10 묶음, 그 뒤는 4개씩). 역할을 끄거나 바꿔도 **탭 이름은 변하지 않습니다.**
6. **관리 엔진** (`bin\manage.mjs`): 관리 창이 하는 모든 일(역할 수정, 내보내기/불러오기, 백업/복구, sync, 실제 창 조회)을 처리합니다. 바꾸기 전에 후보를 **검증**하고, **자동 백업**하고, 파일은 **임시 파일에 쓴 뒤 이름을 바꾸는 방식**(중간에 멈춰도 반쪽 파일이 남지 않음)으로 씁니다.

### 처음 들어 있는 역할 12개

| id | 이름 | 자리 | 모드 | 주기 | 하는 일(요약) |
|---|---|---|---|---|---|
| `commander` | 총지휘 | 0 | 범위 내 쓰기 | 주기적 | 일을 배정하고, 승인을 처리하고, 사용자에게 번호 메뉴로 결정을 받아 보고 |
| `approval-proxy` | 승인 대행 | 0 | 읽기 전용 | 주기적 | 총지휘 창의 승인창에서 권장 선택을 눌러 줌 (**기본 꺼짐**) |
| `approval-reviewer` | 승인 심사관 | 1 | 읽기 전용 | 요청 시 | 승인 대기 창의 위험을 한 줄로 분류해 보고 |
| `ledger-keeper` | 후보·장부관 | 2 | 범위 내 쓰기 | 요청 시 | 프로젝트별 개선 후보를 뽑아 순위를 매기고 장부 유지 |
| `verifier` | 검증관 | 3 | 읽기 전용 | 요청 시 | 푸시 직전 검수 대기열을 PASS/보류로 판정 |
| `human-tasks` | 사람 몫 정리 | 4 | 범위 내 쓰기 | 요청 시 | 사용자 결정이 필요한 항목을 번호 메뉴 후보로 정리 |
| `window-inspector` | 창 상태 점검관 | 5 | 읽기 전용 | 요청 시 | 오래 쉬는 창의 이유를 분류, 재시작 뒤 창 상태 점검 |
| `test-dispatcher` | 시험 지시 | 6 | 읽기 전용 | 요청 시 | 프로젝트별 안전한 읽기 시험을 돌려가며 계획·보고 |
| `doc-consistency` | 문서 정합 감독관 | 7 | 읽기 전용 | 요청 시 | README·PRD가 코드·기록과 맞는지 대조 |
| `git-keeper` | 깃 | 8 | 읽기 전용 | 요청 시 | 조건이 갖춰진 건만 작업 가지로 푸시 |
| `security-guard` | 보안·민감정보 점검관 | 9 | 읽기 전용 | 요청 시 | 푸시·공개 전에 키·토큰·비밀번호·개인정보 혼입 확인 |
| `role-auditor` | 역할 중복·범위 감사관 | 10 | 읽기 전용 | 요청 시 | 역할 겹침과 승인 기록의 범위 준수 점검 |

> 역할 본문(AI 창이 읽는 지시문)은 한국어로 쓰여 있습니다. 위 표는 각 역할 파일의 `summary` 항목을 줄여 옮긴 것이며, 최신 내용은 `roles\*.md` 와 생성된 `역할표.md` 가 정본입니다.

### 부속 기능 (`functions\`)

AI 창을 조회·보조하는 스크립트 5종입니다. **위험도가 높은 것은 설치 때 자동으로 꺼집니다.**

| 기능 | 위험도 | 기본값 | 하는 일 |
|---|---|---|---|
| `pending` | 낮음 | 켜짐 | 승인 대기 중인 창의 명령만 간단히 보여 줌 (읽기 전용) |
| `queue` | 낮음 | 켜짐 | 창 상태 표(`status`), 특정 창 보기(`peek`), 막힌 창 요약(`digest`) 등 (읽기 전용) |
| `watch` — 알림(`alerts`) | 중간 | 켜짐 | 오래 막힌 창·끝난 창·오류를 모아 알림 (읽기만) |
| `watch` — 자동 압축(`auto-compact`) | **높음** | **꺼짐** | 문맥 사용량이 높은 AI 창에 `/compact` 를 대신 입력. `ORCH_AUTOCOMPACT=1` 과 허용 목록이 **둘 다** 있어야 동작 |
| `approve` | **높음** | **꺼짐** | 승인창 **하나**에 안전 조건을 모두 통과할 때만 Enter(예) 또는 Esc(아니요)를 누름 |
| `autopress` | **높음** | **꺼짐** | 승인 대행 창 한 곳의 승인창이 **안전하다고 증명될 때만** "1. Yes"를 누르고, 아니면 사람 확인 요청만 냄. `ORCH_ENABLE_AUTOPRESS=1` 이어야 동작 |

| 명령 | 설명 |

### 역할·생성물

| 명령 | 설명 |
|---|---|
| `node bin\sync.mjs [--out <폴더>]` | 역할표·카드·탭 배치 계획 생성. 옵션: `--config` `--out` `--roles-dir` `--user-roles-dir` `--templates-dir` `--schema` `--env-rules`. 종료코드: 0 성공 / 1 검증·배치 실패 / 2 사용법·설정 오류 |
| `node bin\validate-roles.mjs` | 역할 파일 점검(잘못된 것이 있으면 이유와 함께 종료코드 1) |
| `node bin\render-card.mjs <역할id> --config <설정.json>` | 역할 카드 한 장을 화면에 출력 |
| `node bin\init-config.mjs --orch-home <폴더> --functions-dir <폴더>` | 기본 설정 파일을 **처음 한 번만** 생성(이미 있으면 종료코드 3, 덮어쓰지 않음). 설치 프로그램이 자동으로 부름 |

### 관리 엔진 (`node bin\manage.mjs <명령>`)

관리 창이 내부에서 쓰는 명령입니다. 요청 값은 **표준입력의 JSON**으로 주고(`--request-file <파일>` 로 파일에서 읽거나 `--no-input` 으로 입력 없이 호출도 가능), 결과는 JSON 한 줄로 나옵니다. 종료코드는 성공 0, 실패 1, 명령 오류 2.

| 명령 | 설명 | 주요 요청 값 |
|---|---|---|
| `status` | 현황 | 없음 |
| `role-list` | 역할 목록과 문제 | 없음 |
| `role-set` | 역할 항목 수정 | `id`, `fields`, 선택 `body` |
| `role-new` | 새 역할 | `id`, `fields`, 선택 `from`, `body` |
| `role-revert` | 내 변경을 지우고 번들 기본값으로 | `id` |
| `role-delete` | 내 역할 삭제 | `id` |
| `export` | 묶음 내보내기 | `dest`, 선택 `scope`(`portable`｜`full`), `note` |
| `import-plan` | 불러오기 미리보기 | `pkg`, 선택 `mode`(`merge`｜`replace`) 등 |
| `import-apply` | 불러오기 적용 | `pkg`, `token`(미리보기에서 받은 확인 값) |
| `backup` / `backup-list` | 백업 만들기 / 목록 | 선택 `note` |
| `restore-plan` / `restore-apply` | 복구 미리보기 / 적용 | `pkg`, `token` |
| `sync-run` | sync 실행 | 선택 `out` |
| `live-windows` | 열린 창 조회(읽기) | 선택 `scopePrefix` |

내보내기 범위: `portable` = 내 역할 + `env-rules.md` + `ignore.txt`, `full` = 내 설정 전체.

**세 겹 구조**

| 층 | 위치 | 성격 |
|---|---|---|
| 번들 | 설치 폴더(`app`) | 읽기 전용. `roles`, `templates`, `schema`, `bin`, `lib`, `functions` |

**구성 요소**

```
 [Windows 관리 창]   [Herdr 안 관리 창(모드)]      ← 사람이 보는 화면 (같은 엔진)
 orch-manager.ps1    herdr-mod\orch-manager\*.js
        │                    │
        └──────┬─────────────┘
               ▼
        bin\manage.mjs  (관리 엔진: 검증 → 자동 백업 → 원자적 쓰기)
               │
     ┌─────────┼──────────┐
     ▼         ▼          ▼
```

## 16. 문제·오류 대처 방법

| 증상 | 원인 | 해결 |
|---|---|---|
| 빨간 글씨로 "스크립트를 실행할 수 없습니다 / 서명" | Windows 실행 정책 | 이 문서의 명령처럼 `-ExecutionPolicy Bypass` 를 붙여 실행 |
| `node : 용어가 ... 인식되지 않습니다` | Node.js 미설치 또는 PATH 미인식 | <https://nodejs.org> LTS 설치 → PowerShell **새 창** → `node -v` |
| 설치 점검에서 `중단: Node.js 18 이상이 필요한데 찾지 못함` | Node 없음/구버전 | 위와 같음(18 이상) |
| 설치 점검에 `[경고]` | 선택 기능 부족(세션키퍼 없음, 허용 목록 없음, 상태줄 확인 불가 등) | 설치는 가능. 해당 기능이 필요할 때만 해결 |
| `sync` 경고: `scope_prefix, projects_root 이(가) 아직 '(미설정)'` | 설정 미입력 | `config\orchestration.json` 에 값 입력 |
| 불러오기: `묶음 폴더가 아님` | 상위 폴더를 지정함 | `orch-export-…` **하위 폴더**를 지정 |
| 불러오기: `내용이 기록과 다름(변조 또는 손상)` | 파일이 중간에 바뀜 | 원본 PC에서 다시 내보내기 |
| 불러오기: `미리보기 이후 묶음이나 내 설정이 바뀌었거나…` | 미리보기와 적용 사이에 바뀜 | 미리보기를 다시 한 뒤 적용 |
| 저장이 거부됨(`검증 실패`) | 값이 규칙에 어긋남(예: 모드에 없는 값, 잘못된 id) | 안내된 항목을 고침. 파일은 바뀌지 않았으니 안심 |
| Herdr 모드 설치가 중간에 멈춤 | Herdr 공식 검사 실패 | **아무것도 설치되지 않은 상태**입니다. 안내 글의 이유를 해결하고 재시도 |
| `Ctrl+Shift+M` 이 안 열림 | 그 키를 다른 기능이 쓰는 중이라 설치가 키 연결을 건너뜀 | `Ctrl+Shift+P` → `mod.open orch-manager`, 또는 `-Key` 로 다른 키 지정해 재설치 |
| "실제 창" 탭이 "조회 불가" | `hc` 가 없거나 Herdr 미실행 | `hc` 설치·Herdr 실행 후 새로고침(`F5`) |
| 관리 창이 안 뜸 | PowerShell 5.1 또는 STA 실행 문제 | PowerShell에서 `powershell -NoProfile -ExecutionPolicy Bypass -STA -File bin\orch-manager.ps1` 로 직접 실행해 오류 글을 확인 |
| 설정 위치를 바꿨는데 엉뚱한 곳을 봄 | `ORCH_HOME` 미지정 | 같은 PowerShell 창에서 `$env:ORCH_HOME = "…"` 지정 |

**되돌리고 싶을 때:** 관리 창 **백업·복구** 탭 → 백업 선택 → 미리보기 → 적용. 백업은 `backups\` 폴더에 있습니다.

그래도 해결되지 않으면, 오류 글 **전체**를 복사해 두고 소유자에게 알려 주세요. 단, 글에 포함된 컴퓨터 사용자 이름·경로는 지우고 보내세요.

## 17. FAQ (자주 묻는 질문)

<details>
<summary><b>코딩을 전혀 몰라도 쓸 수 있나요?</b></summary>

설치와 관리 창 사용까지는 이 문서의 명령을 **복사해서 붙여넣기**만 하면 됩니다. 다만 이 도구는 "여러 AI 창을 운영하는 사람"을 위한 것이라, Herdr나 Claude Code를 처음 쓴다면 먼저 그 프로그램들의 기본 사용법을 익히는 것이 좋습니다.

</details>

<details>
<summary><b>Herdr 없이도 쓸 수 있나요?</b></summary>

예. 별도 Windows 관리 창과 `sync`, 백업·복구는 Herdr 없이 동작합니다. 다만 "실제 창" 조회와 Herdr 안 관리 창은 Herdr(와 `hc`)가 있어야 합니다.

</details>

<details>
<summary><b>설치하면 내 컴퓨터의 무엇이 바뀌나요?</b></summary>

`%LOCALAPPDATA%\Herdr-Orchestration` 폴더가 만들어지고 그 안에만 파일이 생깁니다(방법 2를 하면 Herdr 설정의 `mods\orch-manager` 와 `keys.json` 한 줄이 추가됩니다). 시작 프로그램·작업 스케줄러·레지스트리·PATH는 바꾸지 않습니다.

</details>

<details>
<summary><b>업데이트하면 내가 고친 설정과 역할이 사라지나요?</b></summary>

아니요. `config\` (설정과 내 역할)는 **덮어쓰지 않습니다.** 번들(`app\`)만 새 것으로 바뀝니다. 그래도 큰 변경 전에는 관리 창에서 **지금 백업**을 눌러 두세요.

</details>

<details>
<summary><b>어떻게 지우나요?</b></summary>

[19장](#s19)의 제거 명령을 보세요. 기본 제거는 프로그램 파일만 지우고 내 설정·기록은 남깁니다.

</details>

<details>
<summary><b>AI 창에 마음대로 입력을 보내지는 않나요?</b></summary>

기본으로는 보내지 않습니다. 보내는 기능은 `approve`, `autopress`, `watch`의 자동 압축 3가지뿐이고, 모두 **설치 직후 꺼져 있으며** 따로 환경변수로 켜야 합니다.

</details>

<details>
<summary><b>다른 사람이 준 역할 묶음을 가져와도 안전한가요?</b></summary>

경로 조작·파일 변조·크기 초과 같은 **형식 공격은 막도록** 만들고 시험했습니다. 하지만 역할 본문이 AI에게 주는 **지시문**이라, "내용이 악의적인지"는 도구가 판단하지 못합니다. 그래서 불러온 역할을 **꺼진 채로** 받고, 사용자가 읽은 뒤 켜게 했습니다.

</details>

<details>
<summary><b>회사·사업에서 써도 되나요?</b></summary>

**가능합니다. 단, Apache License 2.0의 조건을 지켜야 합니다**(`LICENSE` 사본과 `NOTICE` 유지, 수정 표시 등). 이름·상표는 허락되지 않고, 보증이 없으며, 외부 프로그램(Claude 요금제, Herdr 약관 등)은 **직접 확인**해야 합니다. [18장](#s18)을 보세요.

</details>

<details>
<summary><b>Mac이나 Linux에서 쓸 수 있나요?</b></summary>

지원하지 않습니다. 설치·관리 창이 Windows PowerShell과 Windows 창 기능으로 만들어져 있고, 시험도 Windows 11에서만 했습니다.

</details>

<details>

개발 과정에서 AI 코딩 도구(Claude Code)가 코드 작성과 시험에 참여했습니다. 이 사실은 저작권 문서([18장](#s18))에도 밝혀 두었습니다.

</details>

<details>
<summary><b>왜 영어가 아닌 한국어 역할 본문인가요?</b></summary>

원래 작성자의 운영 환경에서 쓰던 역할 문서를 옮겨 온 것이라 한국어입니다. 영어 문서(`README.en.md`)는 이 안내서의 번역이며, 역할 본문과 화면 글자는 한국어입니다.

<a id="s19"></a>
## 19. 제거 방법과 시험 방법

### 제거

```
powershell -NoProfile -ExecutionPolicy Bypass -File bin\uninstall.ps1 -Check
powershell -NoProfile -ExecutionPolicy Bypass -File bin\uninstall.ps1
```

- 첫 줄은 **지울 목록만** 보여 줍니다. 둘째 줄이 프로그램 파일만 제거합니다(설정·기록·백업은 남음).
- 설정·기록까지 지우려면 둘째 줄 끝에 `-RemoveData` 를 붙입니다. 설치 기록에 없는 파일(내가 만든 것)은 지우지 않고 목록만 알려 줍니다.
- **폴더를 통째로 지우지 않습니다.** 설치 기록의 파일을 하나씩 지우고 비어 버린 폴더만 치웁니다.
- Herdr 안 관리 창 제거: `bin\install-herdr-mod.ps1 -Uninstall`.

### 자동 시험 (개발용 · 선택)

외부 패키지 없이 Node.js로 돌립니다. 시험은 **임시 폴더에서만** 동작하고 내 실제 설정을 건드리지 않습니다.

```
node tests\roles.test.mjs
node tests\install.test.mjs
node tests\manage.test.mjs
node tests\cleanup.test.mjs
node tests\mod-model.test.mjs
node tests\mod-check.test.mjs
node tests\herdr-keys.test.mjs
node tests\herdr-mod-install.test.mjs
node tests\plugin.test.mjs
node tests\functions.test.mjs
bash tests/label-isolation.test.sh
```

- `functions.test.mjs` 는 약 4분 걸리며 시간에 민감한 시험이 있어 **다른 시험과 동시에 돌리지 마세요.**
- `roles.test.mjs` 의 일부(약 12건)는 원작자 PC의 원본 문서와 비교하는 시험이라 **다른 PC에서는 자동으로 건너뜁니다.**
- `mod-check`·`herdr-mod-install` 은 `herdr-app` 이 없으면 건너뜁니다. `label-isolation` 은 Herdr와 `hc` 가 있는 환경용입니다.
- 시험이 `%TEMP%` 에 남긴 임시 폴더는 `node tools\cleanup-test-temp.mjs` (미리보기) 로 확인한 뒤 직접 정리하세요.
- 2026-11-15 기준 개발 PC 결과: functions 278 · install 41 · roles 40 · manage 46 · cleanup 10 · mod-model 15 · mod-check 40 · herdr-keys 9 · herdr-mod-install 9 · plugin 9 · 라벨 격리 10, 실패 0.
