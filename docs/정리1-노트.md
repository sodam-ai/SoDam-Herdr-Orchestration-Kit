## 다음 작업자를 위한 API

모두 `bin/orch-lib.mjs`. **기존 함수의 서명은 그대로**이고, 선택 인자·새 함수만 늘었습니다.

| 이름 | 서명 | 설명 |
|---|---|---|
| `substitute` | `substitute(text, vars, roles = vars.__roles)` | 맨 변수 `{commander}` 등은 예전과 같음. **새:** `{n:<id>}` → 그 역할의 현재 `slot` 숫자, `{name:<id>}` → 그 역할의 현재 `name`. 세 번째 인자 `roles`(= `loadRoles()` 결과)는 선택. |
| `roleVars` | `roleVars(role, roles, config)` (변경 없음) | 돌려주는 객체에 **열거되지 않는** 값으로 `roles`를 실어 둠. 그래서 `sync-lib.mjs`의 `substitute(w, roleVars(r, roles, vcfg))` 같은 **예전 호출이 그대로** `{n:…}`을 풀 수 있음(`Object.keys`는 전과 같은 7개). |
| `renderHeader` / `renderBody` / `renderCard` | 변경 없음 `(tpl, role, roles, config)` / `(role, roles, config)` / `(tpl, role, roles, config)` | 이미 `roles`를 받고 있어 참조 변수가 자동으로 풀림. |
| `resolveRoleRef` (새) | `resolveRoleRef(kind, id, roles)` | `kind`는 `'n'` 또는 `'name'`. 종류·id 형식·존재가 틀리면 `Error`(메시지: "허용되지 않는 변수" / "참조 id 형식이 틀림" / "없는 역할 id 를 참조함" / "역할 목록이 주어지지 않아 … 풀 수 없음"). |
| `findRoleRefs` (새) | `findRoleRefs(text)` → `[{ raw, kind, id }]` | `{종류:값}` 꼴을 전부 찾음(올바른지는 부르는 쪽이 봄). `findVariables`는 맨 변수만 찾는 것 그대로. |
| `ROLE_REF_KINDS`, `ID_PATTERN` (새 export) | `['n','name']`, `/^[a-z][a-z0-9-]{1,30}$/` | 허용 종류와 id 형식(스키마 id 규칙과 같음). |

- 참조는 **본문·머리말 틀·`writes_to`** 어디에 써도 풀립니다(`substitute`를 거치는 곳이면).
- 참조 id는 `id`(파일 이름)이지 번호가 아닙니다. 번호·이름이 바뀌어도 id는 안 바뀝니다(설계서 3장).
- `bin/validate-roles.mjs`: `validate()`가 이제 `{ fails, warns, count }`를 돌려줍니다(`warns`는 새 항목). 경고는 **종료코드 0**이고 stderr에만 나옵니다(`경고 N건 (실패는 아님)`). `sync.mjs`는 종료코드만 보므로 영향이 없습니다.
- 검증 규칙 추가: 본문·머리말 틀·`writes_to`의 참조 종류/형식/존재, `writes_to` 안의 맨 변수가 허용 목록 안인지.

## 결정 기록

- **C4 총지휘 권한**: `mode: scoped-write`, `writes_to: ["{control_dir}/queue.md", "{control_dir}/창-대응표.md", "{control_dir}/README.md"]`. 근거(새 규칙 아님): `docs/C-추출-노트.md` 3장 "총지휘의 `mode`는 지시대로 `read-only`로 했으나, 역할표 10장은 총지휘가 `queue.md`·`창-대응표.md`·`README.md`를 고친다고 한다. 실제로는 `scoped-write`에 가깝다(5-3)", 요청서가 든 근거는 인수인계 3장·역할표 10장의 "같이 고침" 규칙. `CHECKPOINT.md` C4에도 같은 권장.
- **(d) 꺼진 역할을 가리키는 참조 = 경고(종료코드 0)**. 처음에는 실패로 구현했으나 `tests/install.test.mjs`의 (8c)("역할 제거: `enabled:false` → sync 성공")가 깨졌습니다. 이유: 실패로 두면 역할을 끄려면 먼저 다른 역할의 글을 고쳐야 해서 "언제든 제거 가능"(I6 결정)과 충돌. 그래서 경고로 하고 이유를 코드 주석에 적었습니다. 켜진 역할의 글이 꺼진 역할을 가리킬 때만 경고하고(예: 보안 점검관을 끄면 깃·검증관·총지휘에 경고), 꺼진 역할 자신의 글은 경고하지 않습니다. 경고는 stderr 전용이라 아무도 안 볼 수 있다는 약점이 있어, 필요하면 `sync`가 경고를 화면에 보여 주게 하는 후속 작업이 있습니다.
- 참조 풀이는 `roles` 안의 **모든** 역할(꺼진 것 포함)을 대상으로 함 — 꺼도 번호·이름은 계속 풀림.

## 못 한 것·가정

- 머리말의 "역할은 1~10번이고"(역할 개수)는 머리말 문구라 이번 지시 범위(`{role_number}` 등은 그대로) 밖이라 남김. 역할을 늘리면 틀려짐 → 후속(예: `{roles_count}` 변수).
- `{name:…}` 뒤의 조사("깃은"→`{name:git-keeper}은`)는 이름이 받침 없는 말로 바뀌면 어색해질 수 있음(변수 치환의 한계). 지금 이름들에서는 원문과 같음.
- 환경값(<project>, noreply, 소담 문서 규약, 역할 10이 읽는 파일 이름 등 C3 나머지)은 지시대로 건드리지 않음.
- 경고가 stderr로만 나가 `sync` 화면에는 안 보임(`sync.mjs`를 고치지 않음).
- `config.legacy.json` 값(<win> 등)은 시험에서만 쓰였고 새 산출물에 사용자 절대경로를 넣지 않음.
