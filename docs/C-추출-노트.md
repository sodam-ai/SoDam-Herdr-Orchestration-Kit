### 1-3. 새로 쓴 것 (카드가 없던 2개)
`roles/commander.md`, `roles/approval-proxy.md`는 기존 문서의 문장을 재구성했고, 모든 규칙 문장 끝에 `<!-- 출처: 파일명 장 -->`을 달았습니다(검증 도구가 형식과 출처 파일 이름을 강제). 출처 없이 쓴 문장은 없습니다. 아래는 일부러 **싣지 않은 것**입니다.

- 소담 환경 전용 규칙(설계서 A10): `~/.claude/scripts` 쓰기 금지, 가드·`CLAUDE.md` 수정 금지, 삭제는 사용자가 `!`로 실행, noreply 이메일 사용.
- 사용자 개인 정보·습관(비개발자, 쉬운 말, `AskUserQuestion` 도구 이름), "사용자만 할 수 있는 일" 표, 정기 점검(Claude Code 버전 스크립트), 첫 지시문, 역할표 7·8·10장의 일지·결정 기록.
- 인수인계 7장(총지휘 주소 고정 → `/clear` 권장): 라벨 방식(설계서 9-1)이 해결하므로 규칙으로 옮기지 않음.
- 역할표 10장 "같이 고칠 문서" 규칙: sync가 대체하므로 옮기지 않음.
- 승인 대행의 대상 창 이름(`CT-CC-0`/`Master`)과 화면 테두리 제목: 환경값이라 "탭 이름과 화면 테두리 제목으로 찾는다"로만 적음.

## 3. 못 한 것·가정

- `needs`는 전부 비워 둠(지시대로). `approval-proxy`의 짝 기능 `autopress`, 역할 5의 세션키퍼 등은 기능 파일(`functions/`)이 생길 때 채움.
- 읽지 못한 문서(`queue.md`, `ledger.md`, `README.md` 본문)는 이 단계에서도 읽지 않음. 역할 10 카드가 이 파일들을 읽으라고 하므로 이름은 본문에 그대로 남아 있음.
- 가정: `cadence`는 worker 전부 `on-request`(카드가 "총지휘가 요청하면"), 총지휘·승인 대행은 `periodic`(감시 하트비트 / 20초 반복). `reports_to`는 총지휘만 `user`, 나머지는 `commander`. 근거가 약해 사용자 확인 권장.
- 총지휘의 `mode`는 지시대로 `read-only`로 했으나, 역할표 10장은 총지휘가 `queue.md`·`창-대응표.md`·`README.md`를 고친다고 한다. 실제로는 `scoped-write`에 가깝다(5-3).
- 시험은 현재 PC에서 원본이 있을 때만 대조가 실행된다. 원본이 없으면 SKIP이며 실패가 아니다(`ORCH_LEGACY_DIR`로 위치 지정 가능, 기본은 `tests/fixtures/config.legacy.json`의 `control_dir`).
- 검증 도구는 외부 패키지 없이 JSON Schema의 필요한 키워드만 직접 해석한다(전체 표준 구현이 아님).
