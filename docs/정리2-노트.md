## 2. 탭 이름 규칙 (I6)

번호(`slot`) = 자리. 탭 이름은 자리 번호만으로 정해집니다(켜진/꺼진 역할과 무관).

| 자리 | 탭 이름 | 비고 |
|---|---|---|
| 총지휘·승인 대행 (slot 0) | `CT-CC-Master` | 켜진 것만 놓임(승인 대행은 기본 꺼짐). 현재 동작 그대로 |
| 1~4 | `CT-CC-1,2,3,4` | 일부 자리가 비어도 이름 그대로 |
| 5~8 | `CT-CC-5,6,7,8` | 〃 |
| 9~10 | `CT-CC-9,10` | 9번을 꺼도 `CT-CC-10` 이 되지 않음 |
| 11~14 | `CT-CC-11,12,13,14` | 새 자리. 이후 15~18, 19~22 … 4개씩 |
| (자리 범위에 켜진 역할이 0개) | 계획에서 탭이 빠짐 | 다른 탭 이름은 그대로 |

- 접두어(`CT-CC`)·`Master` 글자·4개씩 묶기(`slots_per_tab`)는 설정값입니다. 처음 범위 `[1-4][5-8][9-10]` 은 설정 `layout.tab_groups`(기본값, 생략 가능)로 바꿀 수 있고, 1번부터 빈틈·겹침 없이 이어져야 합니다(아니면 설정 오류, 종료코드 2).
- 같은 자리를 두 역할이 쓰면 검증 실패(원래 있던 규칙, 시험 추가). **꺼진 역할도 자리를 점유**합니다. 다른 역할을 그 자리에 앉히려면 꺼진 역할의 `slot` 을 옮기거나 같은 id 의 내용을 바꾸면 됩니다(아래 "결정 필요" 참고).
- 계획 파일(`layout-plan.json`)의 탭마다 `seats` 가 있어 어떤 자리가 비었는지 알 수 있습니다.

## 3. 내 역할 폴더 로딩·병합 규칙 (I8)

위치: `<ORCH_HOME>\config\roles\` (기본 `%LOCALAPPDATA%\Herdr-Orchestration\config\roles`). 규칙은 `bin/orch-lib.mjs` 의 `loadRolesLayered`(+ `loadAllRoles`, `resolveRoleDirs`) 한 곳뿐입니다.

| 상황 | 결과 |
|---|---|
| 번들 `roles/<id>.md` 만 있음 | 번들 그대로 |
| 내 폴더에 같은 이름 `<id>.md` | **덮어쓰기.** 머리말은 **필드 단위 병합**(내 파일에 적은 필드만 번들 값을 이김, 안 적은 필드는 번들 값). 배열 필드(`writes_to`, `replaces`, `needs`)는 합치지 않고 통째로 대체. 본문은 내 파일에 본문이 있으면 통째로 대체, 비어 있으면 번들 본문 유지 |
| `enabled: false` 한 줄만 적은 같은 이름 파일 | 그 번들 역할이 꺼짐(번들 파일은 그대로). 켜는 것도 같은 방식(`enabled: true`) |
| 번들에 없는 id 의 파일 | **새 역할 추가.** 필수 필드를 모두 적어야 함(`id` 는 생략 가능, 파일 이름으로 채움) |
| 파일 이름 | 확장자를 뺀 이름이 역할 id. id 형식(`^[a-z][a-z0-9-]{1,30}$`)이 아니면 오류(예: `README.md`, `My Role.md`). 머리말에 `id` 가 있으면 파일 이름과 같아야 함 |
| `.md` 가 아닌 파일, 하위 폴더 | 무시(설명 파일은 `README.txt` 로) |
| 심볼릭 링크인 `.md` | 읽지 않고 오류(링크 너머 파일을 따라가지 않음) |

- **fail-closed(실패 쪽으로 닫힘):** 잘못된 파일(머리말 오류, 형식 오류, 모르는 항목, id 불일치, 링크, 같은 자리 겹침, 없는 역할 참조 등)이 **하나라도 있으면** `validate-roles` 가 실패(종료코드 1)하고 `sync` 가 멈춥니다. 건너뛰고 계속하지 않습니다. 생성물은 이전 것이 그대로 남습니다. 오류 메시지에는 `내 역할/<파일>` 처럼 어느 파일인지 나옵니다.
- **보안:** 머리말에 쓸 수 있는 항목은 `schema/role.schema.json`(`additionalProperties: false`)이 정한 12개뿐이라, 기능을 켜는 항목(예: `functions`, `risk`, `autopress`)은 만들 수 없고 쓰면 검증 실패입니다(시험 12c). 역할을 켜는 것(예: `approval-proxy` 역할)은 카드·탭 계획에 나타날 뿐 기능 `autopress` 설정(`orchestration.json` 의 `functions`)은 따로라 바뀌지 않습니다. 변수는 허용 목록과 `{n:<id>}`/`{name:<id>}` 참조만(없는 id 는 오류). 승인 대행의 "파일 수정 자동 승인"은 `config` 폴더 아래(= `config\roles` 포함)를 항상 사람 확인으로 돌립니다(시험 10).
- **`--roles-dir` 만 준 경우**(시험·특수 용도) 내 역할 폴더를 몰래 얹지 않습니다. 내 역할 폴더도 쓰려면 `--user-roles-dir <폴더>` 를 함께 주세요.
- **번들 업데이트:** 재설치·업그레이드는 `config\roles\` 를 만들거나(없을 때만) 건드리지 않습니다. 번들의 같은 역할 본문이 바뀌어도 내 덮어쓰기가 이깁니다(시험 12e). 폴더가 이미 있으면 README 를 지웠어도 다시 만들지 않습니다.
- **제거:** 기본 제거는 데이터(config 포함)를 보존합니다. `-RemoveData` 는 설치가 만든 파일(`ignore.txt`, `orchestration.json`, `config\roles\README.txt`)만 지우고 내가 넣은 역할 파일은 남겨 목록으로 알려 줍니다(기존 정책 그대로).
- 번들 역할 `*.md` 의 `needs` 는 지금 어느 코드도 읽지 않아(안내용) 기능 켜기와 무관합니다.

## 4. 경로 규칙 한 표 (I9, I1, I2)

기준은 `lib/orch-paths.mjs`(node)와 `lib/orch-paths.ps1`(PowerShell)이며 `install.test.mjs (14)`가 둘이 같은 값을 내는지 대조합니다. `install.ps1` 은 번들 점검 전에 위치를 정해야 해서 같은 규칙을 자기 안에 따로 두는데(부트스트랩), 시험 (3b)·(14)가 기본 위치가 같음을 확인합니다.

| 이름 | 값 | 만드는 쪽 |
|---|---|---|
| `home` | `ORCH_HOME` 이 있으면 그것, 없으면 `%LOCALAPPDATA%\Herdr-Orchestration` (`LOCALAPPDATA` 가 비면 `<사용자 폴더>\AppData\Local\Herdr-Orchestration`) | 설치 도구, 시작 시 `ensurePaths()` / `New-OrchDirs` |
| `config` | `<home>\config` (`orchestration.json`, `ignore.txt`, `order.txt`, `compact.off`, `autopress-allow.txt`) | 〃 |
| `roles` (내 역할) | `<home>\config\roles` | **설치 도구만**(빈 폴더 + README.txt, 없을 때만) |
| `state` | `<home>\state` (`served.log`, `round.txt`, `generated\`) | 설치 도구, 시작 시 |
| `docs` (문서 폴더 기본값) | `<home>\state\docs` | **설치 도구만**. 다른 곳을 쓰려면 `-DocsDir` 또는 `ORCH_DOCS_DIR` |
| `logs` | `<home>\logs` | 설치 도구, 시작 시 |
| 번들 | 설치 폴더 `<home>\app` (인자 `-InstallDir` 로 변경) | 설치 도구 |
| `ORCH_TOOL_DIR` | **번들 루트**(`functions\`, `roles\`, `bin\`, `lib\` 가 든 폴더, 설치본은 `<home>\app`) 하나만 인정. 다른 형태·미설정이면 Monitor·pending 자동 승인은 사람 확인 | 사용자가 승인 대행을 켤 때 환경변수로 |

- 불러오기(`import`)·점 불러오기(`. orch-paths.ps1`)·`resolvePaths()` 는 디스크를 건드리지 않습니다(시험 14, functions 8). 폴더를 만드는 것은 `ensurePaths()`/`New-OrchDirs` 를 호출한 스크립트(승인 대행·승인·대기열·감시기)뿐이고, 읽기 전용 `pending.ps1` 은 데이터 폴더를 만들지 않습니다(시험 추가).
- `ensurePaths` 는 `home/config/state/logs` 만 만들고 `roles`·`docs` 는 만들지 않습니다(그건 설치 도구 몫).
- 문서 폴더가 코드(설치) 폴더·설정 폴더와 같거나 포함 관계면 설치 `-Check` 가 중단합니다(승인 대행이 시작을 거부하는 것과 같은 규칙을 미리 적용). 설치 기록(`install-manifest.json`)에 `docsDir` 가 들어가고 제거는 문서 폴더를 지우지 않습니다.
- **S4(도구 폴더 수정은 항상 사람 확인)는 약해지지 않았고 오히려 넓어졌습니다.** 번들 루트 전체(`roles\`, `templates\`, `bin\`, `lib\` 포함)가 코드 영역이 되었습니다. 이전에는 `ORCH_TOOL_DIR` 을 functions 폴더로 두면 `roles\` 등은 영역 밖이었습니다. 옛 설정(`ORCH_TOOL_DIR` = functions 폴더)을 그대로 쓰는 사람은 이제 Monitor·pending 이 자동 승인 대신 사람 확인으로 가므로 안전한 쪽으로 실패합니다(시험 12).

## 6. 알려진 한계

- 꺼진 역할도 자리를 차지합니다(같은 자리에 새 역할을 두면 "slot 겹침" 실패). 자리를 비우려면 꺼진 역할의 `slot` 을 옮기세요.
- 탭 계획만 만듭니다. 실제 창·탭 생성, 라벨 부여는 하지 않았습니다(설계서 9-1 미검증 항목과 같은 범위).
- 내 역할 덮어쓰기의 본문은 "있으면 통째로 대체"뿐입니다(번들 본문에 한 줄만 덧붙이는 기능은 없음). 번들 본문이 크게 바뀐 뒤에도 덮어쓴 본문이 이기므로 번들 업데이트 때 내 본문을 직접 다시 확인해야 합니다.
- 내 역할 파일을 AI 창이 직접 고치는 것은 승인 대행이 자동 승인하지 않지만(config 영역), 사람이 승인한 수정은 막지 않습니다.
- `install.ps1` 의 기본 위치 규칙은 lib 와 별도 사본입니다(부트스트랩). 대조 시험이 어긋남을 잡아 줍니다.
- 설치 `-Check` 는 `ORCH_DOCS_DIR` 환경변수를 읽지만 설치가 환경변수를 영구 설정하지는 않습니다. 기본이 아닌 문서 폴더를 쓰면 승인 대행을 켤 때 같은 값을 환경변수로 줘야 합니다(설치 끝에 안내 출력).
- 여러 줄 명령(I3)·승인창 실화면(I4)·`hc-watch` 해시 고정(I5)·창 라벨(I11)은 이번 범위가 아닙니다.

## 7. 사용자 결정이 필요한 점

1. 꺼진 역할의 자리를 새 역할이 쓸 수 있게 할지(지금은 막음, 안전한 쪽). 허용하면 "켜진 역할끼리만 자리 겹침 금지"로 바뀌고, 꺼진 역할을 다시 켤 때 겹침으로 실패합니다.
2. 내 역할 덮어쓰기의 본문 처리: 지금 "통째로 대체" 한 가지. "번들 본문 뒤에 덧붙임" 같은 방식이 필요한지.
3. 오래된 설정(`ORCH_TOOL_DIR` = functions 폴더)을 쓰던 곳이 있다면 번들 루트로 바꿔야 합니다(이 저장소에는 그런 설정이 실제로 없음).
