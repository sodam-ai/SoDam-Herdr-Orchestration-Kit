# E 단계 노트 — 설치 도구 + sync + 변경 시나리오 시험

- 날짜: 2026-11-13 / 기준 문서: `01_이식-설계서.md` v0.3 (3·4·5·5-2~5-5·6·7·8·10·12장)
- 이미 있던 파일(`roles/`, `templates/`, `schema/`, `functions/`, `lib/`, `bin/orch-lib.mjs`·`render-card.mjs`·`validate-roles.mjs`, 기존 시험 2개)은 **한 글자도 바꾸지 않았습니다.**
- 실제 `hc`는 한 번도 실행하지 않았고 어느 창에도 아무것도 보내지 않았습니다. 시험은 전부 임시 폴더와 가짜 `LOCALAPPDATA`에서만 돌립니다(이 PC의 실제 설정·설치 위치 무영향).
- 작업 스케줄러·시작 프로그램·레지스트리·Herdr 설정·시스템 PATH는 건드리지 않습니다(설치 도구가 그런 코드를 갖고 있지도 않습니다).

## 1. 만든 파일

| 파일 | 내용 |
|---|---|
| `bin/install.ps1` | 점검(`-Check`) → 설치. Windows PowerShell 5.1. 한글이 있어 UTF-8 BOM + CRLF |
| `bin/uninstall.ps1` | 설치 기록(`install-manifest.json`)에 적힌 파일만 하나씩 제거. `-Check`(목록만), `-RemoveData` |
| `bin/sync.mjs` | 역할 파일 + 설정 → `역할표.md`, `cards/<id>.md`, `layout-plan.json` (계획만) |
| `bin/sync-lib.mjs` | sync·설정 생성의 공용 함수. 카드 렌더링은 `orch-lib.mjs`의 함수를 그대로 가져다 씀 |
| `bin/init-config.mjs` | install 이 부르는 작은 도구. 기본 `orchestration.json`을 처음 한 번만 만듦(있으면 종료코드 3, 덮어쓰지 않음) |
| `VERSION` | 번들 버전 `0.1.0` (설치 기록에 들어감) |
| `tests/install.test.mjs` | 자동 시험 17항목 |
| `docs/E-설치-노트.md` | 이 문서 |

## 2. 설계

### 2-1. 설치 흐름
점검(항목별 `OK / 경고 / 중단`) → 중단이 있으면 종료코드 1로 아무것도 설치하지 않고 끝 → (`-Check`면 여기서 종료) → 번들 복사 → 설정·기록 폴더 → 설치 기록 → 복사한 파일 해시를 기록과 다시 대조.
"사용자 확인"은 세션키퍼 설치와 같은 방식입니다: 먼저 `-Check`를 돌려 보고, 괜찮으면 `-Check` 없이 한 번 더 실행합니다(대화형 질문창은 없음).

### 2-2. 위치
| 이름 | 기본값 | 우선순위 |
|---|---|---|
| `-OrchHome` (설정·기록) | `%LOCALAPPDATA%\Herdr-Orchestration` | 인자 > 환경변수 `ORCH_HOME` > 기본값 |
| `-InstallDir` (번들) | `<OrchHome>\app` | 인자 > 기본값 |

설치 기록은 `<OrchHome>\install-manifest.json`에 둡니다(번들 폴더가 아니라 OrchHome. 이유: 번들만 지우고 데이터를 나중에 정리할 때도 기록이 남아 있어야 해서).
기록 내용: 버전, 시각, 번들 파일 목록(상대경로 + SHA-256), 설치가 만든 데이터 파일 목록(`config/ignore.txt`, `config/orchestration.json`).

### 2-3. 기본 설정 `orchestration.json`
| 키 | 기본값 | 설명 |
|---|---|---|
| `scope_prefix`, `projects_root` | `(미설정)` | 사용자가 채움. 값이 `(미설정)`이면 카드에 그대로 들어가고 "이 글자로 시작하는 창"이 없으므로 범위가 **빈 쪽(안전한 쪽)** 으로 실패. sync 가 경고를 출력 |
| `control_dir` | `<OrchHome>\control` | 관제 폴더(역할 2가 `ledger.md`를 씀). 만들지는 않음 |
| `commander_name` | `orch-commander` | 카드의 `{commander}`가 되는 총지휘 창 이름 |
| `layout` | `tab_prefix: CT-CC`, `master_suffix: Master`, `slots_per_tab: 4` | 탭 배치 규칙(아래 3장 1번) |
| `functions` | function.json 에서 계산 | `risk: high`이거나 `default: off`면 `false`. 지금은 `approve`, `autopress`, `watch.auto-compact`가 false, `pending`·`queue`·`watch`·`watch.alerts`가 true |

### 2-4. 점검 항목 (`-Check`)
| 항목 id | 내용 | 못 찾으면 |
|---|---|---|
| `bundle` | roles, templates, schema, bin, lib, functions, VERSION 이 있는가 | 중단 |
| `powershell` | Windows PowerShell 5.1 이상, Windows | 중단 |
| `node` | Node.js 18 이상(PATH, 없으면 `Program Files\nodejs` 등) | 중단 |
| `hc` | PATH 에서 `hc` 찾기(`Get-Command`만, 실행 안 함) | **경고** (설치는 됨, 창을 다루는 기능은 hc 가 생겨야 동작) |
| `herdr-app` | `herdr-app.exe` 찾기 | 경고 |
| `session-keeper` | 세션키퍼 설치 여부 | 경고("역할 5의 창 주소 점검 일부 비활성", 실패 아님) |
| `install-dir` | 기존 설치 기록/폴더 상태: 새로 설치 · 업데이트 · 다른 위치에 이미 설치됨 · 비어 있지 않은 폴더 · 번들=설치 폴더 | 마지막 3개는 중단(`-Force`로 앞 2개만 허용) |
| `config` | 기존 설정이 있는가 | 있으면 "덮어쓰지 않음" 안내(OK) |
| `allow-list` | `scope_prefix`가 정해졌는가 | 경고("자동 압축·승인 대행은 켜지 않음") |
| `statusline` | 상태줄 `컨텍스트 N%` | 항상 경고: 정적 점검 불가, 자동 압축을 켜기 전에 직접 확인 |

### 2-5. sync 가 하는 일
1. `bin/validate-roles.mjs`를 **그대로 실행**해 역할 검증(규칙을 다시 쓰지 않음). 실패하면 종료코드 1, 출력은 건드리지 않음.
2. 설정 점검(키·형식). 실패하면 종료코드 2.
3. 생성물을 메모리에서 모두 계산한 뒤, 총지휘 부재·중복, 창 이름 겹침·형식(`^[a-z0-9_-]{1,32}$`)을 점검. 실패하면 종료코드 1.
4. 파일 쓰기: 내용이 같으면 쓰지 않음. 지난번엔 만들었는데 이번엔 없는 파일(꺼진 역할의 카드)은 `sync-manifest.json`을 보고 **파일 하나씩만** 지움.
5. 시각 같은 흔들리는 값은 넣지 않아 같은 입력이면 항상 같은 바이트가 나옵니다.

생성물: `역할표.md`(자동 생성 머리말, 켜진 역할 표, 꺼진 역할, `replaces` 대응표), `cards/<id>.md`(worker는 머리말 틀 + 본문, commander·proxy는 본문만, 켜진 역할만), `layout-plan.json`(탭별로 어떤 역할이 어떤 이름 `orch-<id>`·라벨 `orch.role`·`orch.slot`·`orch.v`로 놓일지).

## 3. 설계서와 달라진 점·판단한 것

1. **탭 배치를 "그룹 목록"이 아니라 규칙으로 만들었습니다.** 설계서 5-5는 탭 그룹을 적어 둔 목록 같지만, 목록이면 역할을 추가하거나 `slot`을 바꿀 때 목록도 같이 고쳐야 해서 8장의 "역할 파일 변경 + sync 만으로"에 어긋납니다. 그래서 `slots_per_tab`(4)개씩 묶고 탭 이름을 `<접두어>-<켜진 slot 들>`로 만듭니다. 기본 역할 12개에서는 설계서와 똑같이 `CT-CC-Master`(총지휘) / `CT-CC-1,2,3,4` / `CT-CC-5,6,7,8` / `CT-CC-9,10`이 나옵니다(시험으로 확인). 승인 대행은 기본 꺼짐이라 Master 탭에 안 들어갑니다. 역할을 끄거나 `slot`이 바뀌면 탭 이름도 따라 바뀝니다(예: 11번을 추가하면 `CT-CC-9,10,11`). 탭 이름이 바뀌는 것이 싫으면 알려 주세요.
2. **`hc` 와 Herdr 앱이 없는 것은 중단이 아니라 경고로 했습니다.** 설치·sync·카드 생성은 hc 없이 되고, 시험도 hc 없는 환경에서 설치를 돌려야 하기 때문입니다. 지시문의 "경고/중단" 중 경고를 택했습니다.
3. **미설정 값은 빈 문자열이 아니라 `(미설정)` 글자로 둡니다.** 카드에는 "where 가 `X`로 시작하는 창"이라는 문장이 들어가는데, X 가 빈 글자면 **모든 창**이 대상이 되기 때문입니다. `(미설정)`으로 시작하는 창은 없으므로 안전한 쪽으로 실패합니다(설계서 3장 원칙 5, 6장 허용 목록 우선과 같은 방향).
4. **`lib/orch-paths.mjs`는 sync 가 쓰지 않습니다.** 그 파일은 불러오는 순간 폴더를 만들어 버립니다(`--help`만 해도). 같은 규칙(`ORCH_HOME` 우선, 없으면 `%LOCALAPPDATA%\Herdr-Orchestration`)을 만들지 않는 3줄짜리 함수(`resolveOrchHome`)로 따로 두었습니다. 규칙이 바뀌면 두 곳을 같이 고쳐야 한다는 단점이 있습니다.
5. **`commander`·`approval-proxy` 카드 본문에는 `<!-- 출처: ... -->` 주석이 그대로 들어갑니다.** 지시문이 "본문만 치환해 출력"이라 손대지 않았습니다. 창에 붙여넣을 때 주석이 거슬리면 sync 에서 지우는 한 줄을 추가할 수 있습니다(결정 필요).
6. **데이터 정리 범위.** `-RemoveData`는 설치가 만든 `config/orchestration.json`, `config/ignore.txt`만 지웁니다. 프로그램이 나중에 쓴 `state\`·`logs\` 파일과 사용자가 만든 파일은 지시대로 남기고 목록만 알립니다. 그래서 `-RemoveData` 뒤에도 OrchHome 폴더가 남을 수 있습니다(폴더 통째 삭제 금지 규칙과 같은 이유).
7. 번들 파일을 사용자가 직접 고쳤다면(예: 설치된 `roles\verifier.md`) **재설치 때 덮어써집니다**(설계서 3장 원칙 1 "번들은 읽기 전용"). 설치 기록에 없는 파일(사용자가 새로 넣은 역할 파일 등)은 업데이트·제거 모두에서 건드리지 않습니다.

## 5. 못 한 것·가정

- **실제 Herdr·hc 로 시험하지 않았습니다.** 설치 점검의 `OK`(hc 있음, Herdr 앱 있음)는 이 PC 에서 파일을 찾는 수준이고, 대조군은 가짜 `hc.cmd`입니다. 이 단계는 hc 호출이 필요 없습니다.
- 탭 배치는 **계획만** 만듭니다. 실제 탭·창 생성, 라벨 부여(`hc run --label`)는 하지 않았고(설계서 9-1의 미검증 4건과 같은 범위) 이 단계의 범위도 아닙니다.
- 상태줄 `컨텍스트 N%`는 설치 때 정적 점검이 불가능해 안내만 합니다. 화면 글자 점검(`Do you want to` 등)은 구현하지 않았습니다(설계서 10장에는 있으나 지시문에 없었음).
- 설계서 4장의 "② 내 설정: 내가 만든 역할·역할 덮어쓰기 층"은 **만들지 않았습니다.** 지금은 설치된 `roles\` 폴더에 파일을 넣으면 sync 에 나타나고(설치 기록에 없는 파일이라 업데이트·제거에서 보존됨), 번들과 같은 이름의 파일을 고치면 재설치 때 덮어써집니다. 별도 "내 역할 폴더"는 설계서에 필요하다고만 되어 있고 이번 지시 범위(추가 기능 금지) 밖이라 보류했습니다.
- 설치 시험은 `%TEMP%\orch-e-<난수>` 폴더를 시험 뒤에도 남깁니다(폴더 통째 삭제 금지). 쌓이면 사용자가 직접 지우면 됩니다.
- 시험 중 `uninstall`이 자기 자신(`uninstall.ps1`)을 지우는 경로가 이 PC(Windows PowerShell 5.1)에서 정상 동작함을 확인했습니다. 다른 환경에서 실행 중 파일 삭제가 막히면 "경고: 지우지 못함"으로 남기고 계속합니다.
- 작업 중 `git status`(읽기 전용) 한 번을 실행했습니다. 그 외 git 명령은 쓰지 않았습니다.
