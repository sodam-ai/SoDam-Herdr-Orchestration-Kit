SoDam Herdr Orchestration Kit

한국어 | English · 같은 내용의 웹 문서: README.html · README.en.html

여러 개의 AI 창(Claude Code)을 한꺼번에 돌릴 때, 누가 어떤 일을 맡는지(역할) 를 파일 하나로 정해 두고, 그 역할을 다른 컴퓨터로 옮기거나, 고치거나, 백업하고 되돌릴 수 있게 해 주는 도구 모음입니다.

2. 이 도구는 무엇인가요?

한 줄 설명

AI 창 여러 개가 각자 맡은 일(역할) 을 적은 문서를 안전하게 관리하는 도구입니다.

비유로 이해하기

회사에 팀원 12명이 있다고 생각해 보세요. "누가 무슨 일을 하고, 누구에게 보고하는지"를 적은 업무 분장표가 있습니다. 이 도구는 그 분장표를

  • 한 곳(역할 파일)에서만 고치면 모든 안내문이 자동으로 같이 바뀌게 하고,
  • 다른 컴퓨터(새 회사)로 통째로 옮길 수 있게 하고,
  • 고치기 전에 자동으로 사본(백업) 을 만들어 실수해도 되돌릴 수 있게 합니다.

5. 설치 방법

설치 방법은 세 가지입니다. 방법 1을 먼저 하는 것을 권장합니다. 방법 2는 방법 1을 한 뒤에 선택으로 추가합니다.

PowerShell을 프로젝트 폴더에서 여는 법: 탐색기에서 프로젝트 폴더(bin 폴더가 보이는 폴더)를 열고, 위쪽 주소창을 클릭해 주소를 복사합니다. PowerShell을 열고 cd " 를 입력한 뒤 붙여넣고 " 로 닫고 Enter. 예: cd "C:\Users\내이름\Downloads\SoDam-Herdr-Orchestration-Kit"

명령에 -ExecutionPolicy Bypass 가 붙는 이유: Windows는 기본적으로 내려받은 .ps1 실행을 막을 수 있습니다. 이 옵션은 그 한 번의 실행에만 제한을 풉니다. 컴퓨터 전체 설정은 바뀌지 않습니다.

방법 1 — 기본 설치 (필수 · 별도 Windows 창)

1단계: 점검만 해 보기 (아무것도 바꾸지 않습니다)

powershell -NoProfile -ExecutionPolicy Bypass -File bin\install.ps1 -Check

마지막 줄에 점검 결과: 중단 0건 이 나오면 설치할 수 있습니다. 경고는 "설치는 되지만 일부 기능이 제한됨"이라는 뜻이라 정상일 수 있습니다(예: Herdr 세션키퍼가 없음, 허용 목록이 아직 없음). 중단이 하나라도 있으면 그 이유 글을 읽고 해결한 뒤 다시 하세요.

2단계: 설치

powershell -NoProfile -ExecutionPolicy Bypass -File bin\install.ps1

설치가 하는 일:

  • 프로그램 파일을 %LOCALAPPDATA%\Herdr-Orchestration\app 에 복사합니다(보통 C:\Users\내이름\AppData\Local\Herdr-Orchestration\app).
  • 같은 곳에 config(설정), state(작업 기록), logs(로그) 폴더를 처음 한 번만 만듭니다. 이미 있으면 덮어쓰지 않습니다.
  • 위험 기능을 모두 꺼진 상태로 등록합니다.

설치가 하지 않는 일: 시작 프로그램·작업 스케줄러·레지스트리·PATH 변경, 어느 창에든 입력 보내기.

설치 위치를 바꾸고 싶다면 옵션을 덧붙입니다.

옵션뜻
-OrchHome <폴더>설정·기록을 둘 위치(기본: 환경변수 ORCH_HOME, 없으면 %LOCALAPPDATA%\Herdr-Orchestration)
-InstallDir <폴더>프로그램 파일 위치(기본: <OrchHome>\app)
-DocsDir <폴더>문서 폴더(기본: <OrchHome>\state\docs)
-Force비어 있지 않은 다른 폴더에도 설치하도록 허용
-Check점검만

기본 위치가 아니라면: 사용할 때마다 환경변수 ORCH_HOME 을 그 위치로 지정해야 합니다(설치가 끝날 때 안내 글이 나옵니다). 예: $env:ORCH_HOME = "D:\내폴더\orch-home" (이 PowerShell 창에서만 유효).

방법 2 — Herdr 안에서 여는 관리 창(모드) 설치 (선택)

Herdr 앱 안에서 단축키로 여는 창입니다. Herdr가 설치되어 있어야 합니다. 방법 1을 먼저 하세요.

powershell -NoProfile -ExecutionPolicy Bypass -File bin\install-herdr-mod.ps1 -Check

문제가 없으면 -Check 를 빼고 다시 실행합니다.

powershell -NoProfile -ExecutionPolicy Bypass -File bin\install-herdr-mod.ps1

이 설치가 하는 일:

  1. 모드 파일을 임시 폴더에 만들고, Herdr 공식 검사(herdr-app check)를 먼저 돌립니다. 통과하지 못하면 아무것도 설치하지 않고 멈춥니다.
  2. 통과하면 Herdr 설정 폴더의 mods\orch-manager 에 복사합니다(기본 ~\.config\herdr-app).
  3. Herdr의 keys.json 맨 앞에 열기 단축키 한 줄(기본 ctrl-shift-m)을 추가합니다. 먼저 백업(keys.json.bak-before-orch-manager)을 만들고, 결과가 올바른 JSON이 아니면 파일을 그대로 둡니다. 이미 그 키가 쓰이고 있으면 건너뜁니다.

건드리는 곳은 mods\orch-manager 폴더와 keys.json 한 줄뿐입니다. 다른 모드·레이아웃·설정·터미널·대화 기록은 손대지 않습니다.

옵션뜻
-Key <키>열기 단축키 변경(예: ctrl-shift-o)
-NoKey단축키를 연결하지 않음. 명령 팔레트(Ctrl+Shift+P)에서 mod.open orch-manager 로만 엽니다.
-HerdrHome <폴더>Herdr 설정 폴더(기본: 환경변수 HERDR_APP_HOME, 없으면 ~\.config\herdr-app)
-HerdrApp <파일>herdr-app.exe 위치(기본 %LOCALAPPDATA%\Programs\herdr-app\herdr-app.exe)
-Uninstall제거(우리가 만든 파일만 지우고 키 한 줄을 뺌)

방법 3 — Claude Code 마켓플레이스 플러그인 (선택)

이 저장소는 Claude Code 마켓플레이스(.claude-plugin\marketplace.json)이고, 플러그인 이름은 herdr-orchestration-manager(버전 0.1.0) 입니다. 플러그인 안의 설치 도우미 스킬이 위 방법 1과 방법 2를 순서대로 실행해 줍니다. 플러그인 폴더의 install.ps1 을 직접 실행해도 같습니다.

powershell -NoProfile -ExecutionPolicy Bypass -File plugins\herdr-orchestration-manager\install.ps1 -Check

마켓플레이스 주소로 원격 설치하는 과정은 이 문서를 쓰면서 직접 실행해 확인하지 못했습니다. 플러그인 폴더의 설치 흐름 전체는 자동 시험(tests\plugin.test.mjs)에서 확인했습니다.

6. 빠른 시작 (처음부터 끝까지 따라 하기)

전체 소요: 약 5분. 아래를 위에서 아래로 순서대로 하세요.

  1. Node.js 확인: node -v → v18 이상이면 통과 (3장).
  2. 프로젝트 폴더에서 PowerShell 열기 (5장 안내).
  3. 점검: powershell -NoProfile -ExecutionPolicy Bypass -File bin\install.ps1 -Check → 중단 0건 확인.
  4. 설치: -Check 를 뺀 같은 명령.
  5. 설정 파일 열기. 메모장으로 %LOCALAPPDATA%\Herdr-Orchestration\config\orchestration.json 을 엽니다(탐색기 주소창에 %LOCALAPPDATA%\Herdr-Orchestration\config 를 붙여넣으면 이동합니다). 아래 값을 이 컴퓨터에 맞게 고치고 저장하세요.
    항목기본값무엇을 적나요
    scope_prefix(미설정)관리할 Herdr 공간(space) 이름의 앞부분
    projects_root(미설정)프로젝트 폴더들이 모여 있는 상위 폴더

탭하는 일

역할 하나 고치기 (예시)

  1. 관리 창을 엽니다 → 역할 편집 탭.
  2. 목록에서 고칠 역할(예: "검증관")을 클릭합니다.
  3. 값을 고칩니다. 예: 주기를 "요청 시 (on-request)"에서 "주기적 (periodic)"으로.
  4. [저장]. 저장 직전에, 백업할 "내 설정" 파일이 이미 있으면 자동으로 백업이 만들어집니다. (처음 고치는 경우처럼 내 파일이 아직 하나도 없으면 백업할 것이 없어 만들어지지 않습니다. 번들은 바뀌지 않으므로 [번들 값으로 되돌리기] 로 처음 상태로 돌릴 수 있습니다.) 결과가 규칙에 맞지 않으면 아무것도 쓰지 않고 이유를 알려 줍니다.
  5. 저장 후 sync를 다시 실행하면 역할표와 카드가 새 내용으로 바뀝니다(관리 창 "현황" 탭의 [sync 실행 (생성물 갱신)] 또는 10장의 명령).

9. 작동 방법 (내부 원리)

  1. 역할 파일 (roles\*.md): 맨 위 --- 사이에 이름·요약·자리·모드·주기·보고 대상 같은 항목이 있고, 아래에 AI 창이 따를 본문이 있습니다. 항목 형식은 schema\role.schema.json 이 정합니다.
  2. 내 역할 폴더 (<설정 위치>\config\roles): 같은 id의 파일을 두면 번들 역할을 덮어쓰고(바꾼 항목만 적으면 됨), 새 id는 새 역할이 됩니다. 업그레이드해도 이 폴더는 건드리지 않습니다.
  3. 설정 (orchestration.json): 경로·이름은 코드에 적지 않고 여기서 읽습니다.
  4. sync: 역할(번들 + 내 역할)과 설정을 합쳐 역할표.md, 역할 카드(cards\<역할id>.md), 탭 배치 계획(layout-plan.json), 목록(sync-manifest.json)을 만듭니다. 계획과 문서만 만들고, 창을 만들거나 hc 를 부르거나 어느 창에도 아무것도 보내지 않습니다. 검증에 실패하면 이전 출력을 그대로 둡니다.
  5. 탭 배치 규칙: 탭 이름은 자리 번호로 정해집니다(기본: 자리 1~4, 5~8, 9~10 묶음, 그 뒤는 4개씩). 역할을 끄거나 바꿔도 탭 이름은 변하지 않습니다.
  6. 관리 엔진 (bin\manage.mjs): 관리 창이 하는 모든 일(역할 수정, 내보내기/불러오기, 백업/복구, sync, 실제 창 조회)을 처리합니다. 바꾸기 전에 후보를 검증하고, 자동 백업하고, 파일은 임시 파일에 쓴 뒤 이름을 바꾸는 방식(중간에 멈춰도 반쪽 파일이 남지 않음)으로 씁니다.

17. FAQ (자주 묻는 질문)

코딩을 전혀 몰라도 쓸 수 있나요?

설치와 관리 창 사용까지는 이 문서의 명령을 복사해서 붙여넣기만 하면 됩니다. 다만 이 도구는 "여러 AI 창을 운영하는 사람"을 위한 것이라, Herdr나 Claude Code를 처음 쓴다면 먼저 그 프로그램들의 기본 사용법을 익히는 것이 좋습니다.

Herdr 없이도 쓸 수 있나요?

예. 별도 Windows 관리 창과 sync, 백업·복구는 Herdr 없이 동작합니다. 다만 "실제 창" 조회와 Herdr 안 관리 창은 Herdr(와 hc)가 있어야 합니다.

설치하면 내 컴퓨터의 무엇이 바뀌나요?

%LOCALAPPDATA%\Herdr-Orchestration 폴더가 만들어지고 그 안에만 파일이 생깁니다(방법 2를 하면 Herdr 설정의 mods\orch-manager 와 keys.json 한 줄이 추가됩니다). 시작 프로그램·작업 스케줄러·레지스트리·PATH는 바꾸지 않습니다.

업데이트하면 내가 고친 설정과 역할이 사라지나요?

아니요. config\ (설정과 내 역할)는 덮어쓰지 않습니다. 번들(app\)만 새 것으로 바뀝니다. 그래도 큰 변경 전에는 관리 창에서 지금 백업을 눌러 두세요.

어떻게 지우나요?

19장의 제거 명령을 보세요. 기본 제거는 프로그램 파일만 지우고 내 설정·기록은 남깁니다.

AI 창에 마음대로 입력을 보내지는 않나요?

기본으로는 보내지 않습니다. 보내는 기능은 approve, autopress, watch의 자동 압축 3가지뿐이고, 모두 설치 직후 꺼져 있으며 따로 환경변수로 켜야 합니다.

다른 사람이 준 역할 묶음을 가져와도 안전한가요?

경로 조작·파일 변조·크기 초과 같은 형식 공격은 막도록 만들고 시험했습니다. 하지만 역할 본문이 AI에게 주는 지시문이라, "내용이 악의적인지"는 도구가 판단하지 못합니다. 그래서 불러온 역할을 꺼진 채로 받고, 사용자가 읽은 뒤 켜게 했습니다.

회사·사업에서 써도 되나요?

가능합니다. 단, Apache License 2.0의 조건을 지켜야 합니다(LICENSE 사본과 NOTICE 유지, 수정 표시 등). 이름·상표는 허락되지 않고, 보증이 없으며, 외부 프로그램(Claude 요금제, Herdr 약관 등)은 직접 확인해야 합니다. 18장을 보세요.

Mac이나 Linux에서 쓸 수 있나요?

지원하지 않습니다. 설치·관리 창이 Windows PowerShell과 Windows 창 기능으로 만들어져 있고, 시험도 Windows 11에서만 했습니다.

이 도구는 AI가 만들었나요?

개발 과정에서 AI 코딩 도구(Claude Code)가 코드 작성과 시험에 참여했습니다. 이 사실은 저작권 문서(18장)에도 밝혀 두었습니다.

왜 영어가 아닌 한국어 역할 본문인가요?

원래 작성자의 운영 환경에서 쓰던 역할 문서를 옮겨 온 것이라 한국어입니다. 영어 문서(README.en.md)는 이 안내서의 번역이며, 역할 본문과 화면 글자는 한국어입니다.
